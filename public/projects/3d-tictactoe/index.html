How the AI picks a move: three checks, in order

Every turn it runs the same three steps from ai.rs. The panel beside the board shows which one decided its last move.

  1. 01

    Win if it can

    If one empty cube completes an AI line, it plays there. No search needed.

    if let Some(m) = self.find_winning_move(state, Player::AI) {
    return Some(m);
}
  2. 02

    Block if it must

    If you have two in a line and the third cube is empty, it takes that cube.

    if let Some(m) = self.find_winning_move(state, Player::Human) {
    return Some(m);
}
  3. 03

    Play it out 2,000 times

    Otherwise it splits 2,000 playouts across the empty cubes. Each playout finishes the game with 70% sensible moves and 30% random ones. The best average result, plus a small bonus for central, corner and open-line cubes, wins.

    let sims_per_move = self.simulations / empty.len() as u32;
let final_score = avg_score + position_value;

49 ways to win on a 3×3×3 board

Flat tic-tac-toe has 8 lines. Stack three boards and you get 27 straight lines along the axes, 18 diagonals across the faces, and 4 diagonals from corner to corner through the center cube.

The center sits on 13 of them, which is why both players want it first. check_winner tests all 49 after every move.

Architecture: Bevy systems that run every frame

Bevy is an entity-component-system engine. Each of the 27 cubes is an entity tagged with its x, y and z, and the game itself is one GameState resource. main.rs registers eleven systems that run every frame; these are the ones a move passes through.

3 problems I solved to make it playable

Clicking a cube you can barely see

The center cube is boxed in on every side, and from any angle most cubes sit behind others. The click has to land on the one you mean.

The problem

In a 3×3×3 grid most cubes are behind other cubes from any angle. Picking by screen position would grab the front cube, and a filled cube in front would make an empty one behind it unreachable.

How I solved it

  • Every frame, the cursor becomes a ray through the camera, and the ray is tested against each cube's box with a slab test I wrote for it.
  • Only empty cubes are tested, so filled cubes never block the one you're aiming for, and the nearest hit wins.
  • Cubes are 0.8 wide on a 2.0 grid, so there are gaps to aim through to the inner ones, and the camera orbits to any angle.
  • A click only plays the cube that's lit, so what you see highlighted is what you get.
let mut tmin = (box_min.x - ray_origin.x) / ray_dir.x;
let mut tmax = (box_max.x - ray_origin.x) / ray_dir.x;
// same for y and z, then keep the overlap

The result

Every one of the 27 cubes can be picked, including the center.

Random playouts miss the obvious

Pure random games treat a one-move win like any other move. With 27 options there are only 74 playouts per cube.

  1. 1Can I win now?play it
  2. 2Can they win now?block it
  3. 3Otherwise2,000 playouts

The problem

A Monte Carlo AI is only as good as its playouts. With fully random games, a cube that wins on the spot and a cube that loses next turn can average out the same, and the AI would let you finish a line.

How I solved it

  • Before any search, it checks every empty cube for an immediate win, then for a cube that blocks yours.
  • Inside playouts, 70% of moves use the same win-then-block rule and then pick among the three most central or corner cubes; 30% stay random so games vary.
  • Each candidate's average result gets a small position bonus: closeness to the center, corners, and how many lines through it you haven't blocked.
let chosen = if rng.gen_bool(0.7) {
    self.choose_smart_move(&state, player, &moves)
} else {
    /* 30%: any empty cube, picked at random */
};

The result

It never misses a one-move win or block, and it answers in milliseconds.

Seeing where the AI just played

A new cube among 26 others is easy to miss, and an instant reply feels like nothing happened.

The problem

The AI decides in a few milliseconds, so its cube would appear the same frame you clicked. In 3D, a cube changing colour somewhere in the grid doesn't catch the eye.

How I solved it

  • The AI system waits 1.5 s, while the status reads "Smart AI calculating…".
  • Each placed cube starts at 0.1 scale and grows back over half a second with an ease-out curve, spinning twice and landing square.
  • Hover highlights only show on your turn, and every new game gets a randomly placed, slightly tinted light so the board doesn't look the same twice.
let eased = 1.0 - (1.0 - progress).powi(3);
let spin = progress * 2.0 * TAU * (1.0 - eased);
transform.rotation = Quat::from_rotation_y(spin);

The result

You can see every move land, from any angle.

Run the original on your machine

cd 3DTicTacToe
cargo run --release

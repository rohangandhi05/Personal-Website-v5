A Chrome extension for live chess analysis

A solo project. The extension reads the position straight from Chess.com's page, runs Stockfish as WebAssembly in an offscreen document, and draws the engine's top three moves in a panel beside the board.

Project overview: two platform limits to work around

Chess.com offers no API for a game in progress, and a Manifest V3 service worker can't start the Web Worker an engine needs. Most of the work went into those two limits: rebuilding the position from the page's markup, and hosting Stockfish in an offscreen document.

I designed, built and published it to the Chrome Web Store on my own.

      Reading the chess board from the page's markup

      Each piece on Chess.com is an element whose class names its colour, type and square. The content script turns those classes into a FEN string, the format engines read, and counts the move list to know whose turn it is.

      When the board can't be read, it replays the move list through chess.js instead.

      Architecture: 4 extension parts pass each move along

      A service worker can't host Stockfish, so it opens an offscreen document that does. The worker tags every request with an id and keeps a queue, so each answer goes back to the tab that asked, and an answer for a position that has already changed is dropped.

      3 problems I solved to keep the analysis right mid-game

      Scraped move text is messy

      Moves arrive with clocks, symbols and annotation marks. I clean each token and match it against chess.js's legal moves, so a bad scrape can't build an illegal position.

      "1. e4"e4
      "Nf3 0:42"Nf3
      "N×e5+"Nxe5
      "Rxd4!?"Rxd4

      The problem

      Chess.com puts piece icons in child spans, clocks like "0:42" beside moves, and marks like "!?" and "+" in the move list, and the markup differs between live games, puzzles and reviews. Rebuilding the game from that text meant one misread token threw off every position after it.

      How I solved it

      • Read the board itself first: each piece element's CSS classes give its square, and the count of data-ply nodes gives whose turn it is. chess.js has to accept the FEN before it's used.
      • If that fails, replay the move list. _cleanMoveText strips glyphs, clocks, annotations and move numbers, and a SAN regex drops anything that still isn't a move.
      • Every selector runs and the one with the most valid moves wins, so a selector that stops early can't cut the game short.
      • A token chess.js rejects goes through five fallbacks (capture by target square, castling, square only, file disambiguation, best guess), each picked from chess.js's own legal moves.
      const clean = this._cleanMoveText(raw)
const result = chess.move(clean, { sloppy: true })
if (result) return result
// else: capture, castling, square, file, best guess

      The result

      Every position sent to Stockfish is one chess.js accepts as legal.

      The engine should work on your turn

      The content script tracks whose move it is. On the opponent's turn the panel says so and leaves the engine free for your next position.

      ♟ Analysis
      Best move--Opponent's turn

      The problem

      The board changes on both players' moves. Analysing every change spent engine time on positions the user couldn't play, and a slow result could arrive after the next move, showing advice for a position that was already gone.

      How I solved it

      • The user picks White or Black in the panel once. The side to move comes from the ply count: even means White.
      • On the opponent's turn the content script shows "Opponent's turn" and returns before messaging the service worker, so Stockfish sits idle.
      • Each request gets an increasing analysisId. A reply whose id isn't the latest is dropped.
      if (currentTurn !== this.myColor) {
  this.updateBestMove('--', "Opponent's Turn")
  return
}

      The result

      The panel only shows lines for the current position, and only on your move.

      Updates break the open tab's link

      A Chrome update invalidates the content script's connection. I catch the lost-context error and ask for a reload instead of failing silently.

      Extension reloadedPlease reload this page to reconnectReload page

      The problem

      When Chrome updates or reloads an extension, tabs that are already open keep running the old content script, but its link to the extension is gone. sendMessage then fails with "Extension context invalidated", and nothing told the user why the panel had stopped.

      How I solved it

      • Before sending, check chrome.runtime?.id. In the reply callback, check chrome.runtime.lastError. Both reject with a clear "please reload" error.
      • The catch block spots that error, switches the panel to "Reload page" and shows a red prompt with a reload button.
      • It only reacts if the failed request is still the latest, so an old request can't overwrite a newer result.
      if (!chrome.runtime?.id) {
  reject(new Error('Extension context lost - please reload the page'))
}

      The result

      A broken connection becomes a one-click fix instead of a panel that silently stops.

      Known limits and fair-play rules

      Built for practice against bots and for reviewing my own games. The README covers the rest.

      Read the README
      ♟Chess AnalyzerStockfish · chess.com
      Active on chess.com

      Select White or Black on the overlay to start. Press H to hide the panel.

      For educational use only. Engine help in rated games breaks chess.com's Terms of Service.

      Is it meant for rated games?

      No. Engine help in rated games breaks Chess.com's fair-play rules, and the popup and README say so. It's for bot games, casual play and going over finished games.

      Where does the analysis run?

      On the user's machine. Stockfish runs as WebAssembly inside Chrome, and the extension only has access to chess.com.

      What does the position miss?

      En passant and the 50-move counter aren't in the FEN it builds, and a king or rook that leaves its square and comes back still looks able to castle. Replaying the full move list through chess.js would fix all three.

      What if Chess.com changes its board?

      The reader depends on Chess.com's class names. The move-list fallback covers small changes; a redesign means new selectors.

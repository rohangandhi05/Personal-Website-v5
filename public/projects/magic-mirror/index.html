If the weather or traffic call throws, the app swaps in built-in values and marks the result as offline data. Tests check that flag when the weather or the traffic data comes back empty.

3 problems the mirror's code handles

Three APIs, three unit systems

MapQuest answers in miles, Google in metres and OpenWeatherMap in Kelvin. The mirror has to show one consistent set.

282.15 K→9 °C 8.82 mi→14.2 km 14200 m→14.2 km

The problem

Each provider returns its own entity shape and units. Converting inside each service would spread the same math across the app, and swapping MapQuest for Google would mean touching the display code.

How it's solved

  • Each API response deserializes into its own entity class in the data-access layer.
  • AutoMapper profiles map every entity onto one shared model, and a second profile maps that onto the view model the console prints.
  • The math lives once, in Acme.Generic: Kelvin to Celsius, miles and metres to km, Unix seconds to a time of day.
  • Those helpers have their own tests against known inputs.
public static double KelvinToCelsius(double value, int precision = 2)
{
    double converted = value - 273.15;
    ...
}

The result

The view model always holds °C and km, whichever API answered.

An API can fail at 7am

A mirror that shows an error, or nothing, is worse than no mirror. A failed call falls back to built-in data and says so.

GET api.openweathermap.org → 503 ↓ IsOfflineData = true · Sunny, 17 °C

The problem

The briefing depends on two network calls, and the mirror sits on a home network that drops. An unhandled exception would leave the screen blank until someone restarted the app.

How it's solved

  • Both calls run inside one try block when the view model is built.
  • On any exception the app logs it, loads built-in weather and traffic models, and sets IsOfflineData on the view model.
  • Tests mock an empty weather response and an empty traffic response and assert the flag is set, and that a good response leaves it unset.
catch (Exception ex)
{
    weatherModel = GetOfflineWeatherData();
    trafficModel = GetOfflineTrafficData();
    model.IsOfflineData = true;
}

The result

The screen is never blank, and offline values are labelled as offline.

There's no YouTube app for a mirror

The cast module makes the mirror pass as a smart TV, so the phone's own cast button works. I added it and placed its window.

Cast to Living room TV MagicMirror

The problem

YouTube only casts to devices it recognises, and a Raspberry Pi running a web dashboard isn't one. The video also had to sit in one corner without covering the rest of the mirror.

How it's solved

  • The module (Kevin Townsend's MMM-Screencast, MIT) runs a DIAL server, the discovery protocol smart TVs use, so the mirror shows up in the cast list.
  • On cast it spawns an Electron window that sends a Samsung Tizen TV user agent, so youtube.com/tv serves the TV interface and pairs with the phone.
  • The mirror and the window are separate processes talking over IPC; stopping the cast sends QUIT and the window closes.
  • My part: installing it on the Pi and setting the region, window position and size in the config.
const userAgent = 'Mozilla/5.0 (SMART-TV; Linux; Tizen 2.4.0) ...'
electron.session.defaultSession.setUserAgent(userAgent)

The result

Any phone with YouTube casts to the mirror with no app to install.
